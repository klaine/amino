# Contributing to Amino

Bug reports, preset ideas and pull requests are welcome. For anything bigger than a small fix, open an
issue first so we can agree on the approach.

- **Branch:** fork, branch from `main`, and open the pull request against `main`. Don't touch the
  `pages` branch: it's generated by `scripts/pages.sh` and replaced on every publish.
- **Build and test:** `scripts/build.sh` runs the contract, native, UI and golden tests, then builds
  `dsp.so` and the package. It needs [zig](https://ziglang.org) (`brew install zig`) and Python 3. The
  web synth is `scripts/build_web.sh`. Run both before you open a pull request.
- **Generated files:** parameters live in `tools/gen/params.py`, and `gen.py` writes the C tables, the
  contract and the module folder from it. Edit the `src/` copy of a UI file, never the generated copy
  in `modules/`, then run `scripts/build.sh --gen`.
- **Sound changes:** `tests/golden/golden.json` covers all 324 factory presets. If a change to the
  sound is intended, regenerate it with `tests/golden/check_golden.py build/amino_golden --write` and
  say why in the pull request. Don't rewrite it just to make a failure go away.
- **Realtime:** no allocation, file I/O or logging on the audio thread.
- **Wavetables and presets:** only contribute material you made or that is freely licensed, and note
  the source and license. See [docs/07](docs/07-wavetables-and-ip.md) for what is allowed.
- **Style:** match the surrounding code. Keep commits focused, with a message that says why.

By contributing you agree your work is released under the repository's [LICENSE](LICENSE).
